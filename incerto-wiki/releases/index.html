Releases

Incerto Wiki uses versioned releases for stable chapter cycles. A release is not a promise that the whole wiki is complete; it is a named, reproducible state of a coherent slice of the project.

Release Gates¶

A stable chapter-cycle release should pass these checks before a Git tag is cut:

  • python -m pytest

  • jupyter-book build --html --execute

  • python scripts/provenance_footer.py --check

  • browser smoke checks on representative concept, reading-guide, and table pages

  • print smoke checks on representative pages when CSS or page structure changed

Version Scheme¶

Use semantic-looking vMAJOR.MINOR.PATCH tags, with conservative meanings:

  • MAJOR: incompatible site or package structure;

  • MINOR: a stable chapter cycle or substantial concept-family release;

  • PATCH: corrections that do not change the cycle scope.

The package version in pyproject.toml, the release page, and the Git tag should agree when a release is published.

The tag workflow at .github/workflows/release.yml enforces that agreement for v*.*.* tags and uploads the built static site as a release artifact.

Release Notes¶

Each release note should record:

  • scope and exclusions;

  • verification commands;

  • important source or data caveats;

  • known gaps that remain intentionally open.
